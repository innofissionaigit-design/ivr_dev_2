USER STORY
As a frustrated caller, I want to be heard and offered a person, so that my
frustration is not compounded by a machine.

ACCEPTANCE CRITERIA
1. Anger lowers the escalation threshold.
2. Delivery slows.
3. A human is offered explicitly rather than continuing to transact.
4. The agent apologises once.
5. The agent does not argue.
6. The agent does not defend the hospital.
7. The complaint/frustration is captured in the context packet.

1. AC-BY-AC STATUS
================================================================================

AC1 -- Anger lowers the escalation threshold: PASS
    Evidence: The investigation found CallState.escalation_threshold was
    written by responses/speech_policy.py's dormant "angry" row but had NO
    reader anywhere in the codebase -- wiring a reader up would have been
    the "generic escalation framework" instruction 3 explicitly forbade.
    Per the investigation's own recommendation, the threshold-lowering is
    implemented as the new guard's own eligibility rule instead: an angry
    caller reaches an explicit human offer on the VERY FIRST angry
    utterance (main.py::_finish_anger(), called from both _resolve_intent()
    and _continue_pending()), with no other justification needed -- the
    same way agent/human_fast_path.py's mere existence already encodes "a
    direct human request needs zero other justification to escalate." A
    normal caller only reaches a human offer via an explicit request, an
    out_of_scope/clinical_interpretation/unverifiable_claim guard, or three
    consecutive low-ASR-confidence turns (session.confirm_attempts > 2).
    Anger skips straight past all of that on turn one. The
    escalation_threshold="low" field value is also honestly set on
    session.call_state (see AC2) so it is correctly reported wherever
    CallState.as_dict() is logged, even though it is not itself the trigger.
    Tests: tests/test_anger_flow.py::TestCallStateActivation::
    test_finish_anger_sets_escalation_threshold_low; TestGuardOrderIn
    ResolveIntent (proves the guard fires on turn one, unconditionally);
    TestExistingGuardsStillWinWhereTheyShould::test_confirm_attempts_
    escalation_path_is_untouched_for_non_angry_callers (proves the normal
    3-strikes path is unmodified).

AC2 -- Delivery slows: PASS
    Evidence: main.py::_finish_anger() rebuilds session.call_state via the
    existing agent/call_state.py::build()/responses/speech_policy.py
    machinery with caller_state="angry", which resolves to
    speech_rate="slow_normal" -- the exact dormant "angry" row the
    investigation identified. main.py's own _speak() already reads
    session.call_state.speech_rate on every turn (a pre-existing, live
    code path) and threads it into TTSClient.synthesize(), which the
    already-live SPEECH_RATE_SCALE table maps to a real length_scale. No
    new speech-rate mechanism was created.
    Tests: TestCallStateActivation::test_finish_anger_activates_slow_
    normal_speech_rate; test_the_speech_rate_this_story_writes_is_what_
    speak_already_reads; test_non_angry_normal_caller_call_state_is_
    unaffected (regression).

AC3 -- A human is offered explicitly rather than continuing to transact:
PASS
    Evidence: Unlike Story 2's complaint flow (a silent, immediate
    handoff), _finish_anger() speaks anger_reply() -- which explicitly
    asks "would you like me to connect you with one of our staff, or
    would you rather contact our counter directly?" -- and then opens
    session.pending = {"awaiting": "angry_choice", "retries": 0}, the same
    offer-then-wait pending mechanism "out_of_scope_choice"/"clinical_
    interpretation_choice"/"unverifiable_claim_choice" already use. "yes"
    -> human_fallback_reply() + record_human_handoff("caller_angry"); "no"
    -> out_of_scope_counter_reply(); an unclear answer retries (re-asking
    the offer only, never re-apologising) then falls through to fresh
    classification after two retries. No live-transfer promise is made
    that this system cannot keep -- the offer wording is the same fixed
    sentence every sibling guard-offered choice already speaks. Per
    instruction 9, anger also interrupts (rather than finishing) any
    in-progress booking/report/billing/doctor-lookup/callback flow before
    making this offer.
    Tests: TestAngerIntentDispatch (opens the pending state, no false
    live-transfer wording); TestAngryChoiceHandler (yes/no/retry-then-
    fall-through); TestAngerInterruptsPendingFlow (booking/report/
    billing/doctor-lookup).

AC4 -- The agent apologises once: PASS
    Evidence: Per the story's own binding design decision ("once per
    call, not once per angry utterance"), a new session.anger_apologized
    boolean (plain, mutable CallSession attribute -- not on the frozen,
    wholesale-rebuilt CallState) is read at the top of _finish_anger() and
    set True at the end. anger_reply(already_apologized, language) has two
    fixed variants: apology-plus-offer the first time, offer-only every
    time after -- the human offer is never weakened or dropped on repeat,
    per the story's own explicit instruction. This deliberately does NOT
    reuse Story 2's own per-turn-repeatable apology behaviour
    (complaint_acknowledged_reply() apologises every time a complaint is
    filed in the same call) -- the two stories keep their own, separately
    tested apology semantics.
    Tests: TestApologyOnce (first utterance apologises; second/third/many
    do not; human offer never weakens); test_apology_flag_lives_on_the_
    session_not_call_state.

AC5 -- The agent does not argue: PASS
    Evidence: is_anger() is a deterministic, pure phrase-matching guard
    (agent/anger_flow.py) checked inside _resolve_intent() and
    _continue_pending() BEFORE fast_path, the semantic cache, or the LLM
    ever run -- proven structurally (not just by the reply's wording) by
    wiring exploding stand-ins for all three and confirming an angry
    utterance never reaches them. anger_reply()'s own text is a fixed,
    non-generative template (never model-composed), so the model is never
    given a turn in which it could argue.
    Tests: TestGuardOrderInResolveIntent (structural short-circuit proof,
    parametrised across all three language surfaces); TestAngerReply
    NeverArguesOrDefends::test_never_contains_forbidden_argue_or_defend_
    language.

AC6 -- The agent does not defend the hospital: PASS
    Evidence: Same deterministic fast-path mechanism as AC5 -- anger_
    reply()'s fixed text never justifies, explains, or defends the
    hospital or its staff, and the guard's placement means no downstream
    branch that could generate defensive text is ever reached for an
    angry turn.
    Tests: TestAngerReplyNeverArguesOrDefends (forbidden-phrase list
    checked against both reply variants, all 4 languages spoken-
    punctuation-clean); TestAngerIntentDispatch::test_no_other_tool_is_
    called (proves no lookup/resolution attempt is even made).

AC7 -- The complaint/frustration is captured in the context packet: PASS
    Evidence: _finish_anger() calls agent/tools_client.py::submit_
    complaint(text) -- the SAME call site and SAME clinic-api
    ComplaintRecord table Story 2's own complaint flow already uses --
    with the caller's utterance passed through verbatim. No second
    complaint-storage system was built, per the story's own explicit
    design decision. A tool failure here is caught and logged but never
    blocks the spoken reply or the human offer (AC3 must hold even if
    context-capture fails). Detection is also recorded in the shared
    escalation ledger via a NEW, separate event (agent/outcomes.py::
    record_anger_detected() / ANGER_DETECTED_EVENT) rather than being
    folded into record_human_handoff() -- see section 3 below for why.
    Tests: TestAngerIntentDispatch::test_captures_the_utterance_verbatim_
    via_submit_complaint; test_records_the_anger_detected_audit_event;
    test_tool_failure_still_speaks_the_reply_and_offers_a_human.

Overall: 7/7 acceptance criteria PASS.

3. KEY DESIGN DECISIONS (beyond what the prompt specified verbatim)
================================================================================

- Anger vs. complaint overlap ("enhance, don't compete", instruction 8):
  implemented ENTIRELY as guard order. is_complaint(text) is checked
  strictly before is_anger(text) in both _resolve_intent() and
  _continue_pending(), so an utterance matching both is routed through
  Story 2's own, completely unmodified complaint flow (one acknowledgment,
  which already contains an apology, one record, one silent handoff).
  agent/anger_flow.py's own guard is never even reached for that
  utterance. Zero changes were made to agent/complaint_flow.py or
  _finish_complaint().

- Anger vs. an explicit human request: is_immediate_human_request() is
  checked before both is_complaint() and is_anger() in _resolve_intent()'s
  existing, unmodified guard order -- an explicit "connect me to a human"
  wins outright over an angry-sounding utterance, the more absolute of
  the two asks.

- Why record_anger_detected() is its OWN event, not routed through
  record_human_handoff(): unlike Story 2's complaint flow (a single,
  silent handoff with no yes/no step), this story's own "angry_choice"
  pending state asks a real question and, on "yes", separately calls
  record_human_handoff("caller_angry", ...) itself (the same pattern
  every sibling guard-offered choice already uses). Folding detection
  into that same counter/ledger tag would double-count every angry call
  that also said "yes", and would show a "handoff" for a caller who said
  "no". This mirrors the existing detected-vs-escalated separation
  record_unverifiable_claim()/record_human_handoff() already keep for
  their own guard+choice pair.

- Where the once-per-call apology flag lives: a new plain
  session.anger_apologized boolean on the non-frozen CallSession (like
  session.pending), not on the frozen, wholesale-rebuilt CallState.

- CallState mutability: confirmed CallState is a frozen dataclass (fields
  cannot be mutated directly), but session.call_state is a plain,
  freely-reassignable CallSession attribute. "Activating" anger state is
  therefore a single reassignment to a freshly built() CallState, the
  same pattern session.pending already uses throughout this file -- no
  new mutability mechanism was introduced.

6. THE ONE REGRESSION THIS STORY DID INTRODUCE, AND ITS FIX
================================================================================

tests/test_spoken_punctuation.py::test_the_gate_covers_every_public_reply_
function failed once anger_reply() was added to agent/reply_templates.py:
that test asserts every public function in reply_templates.py has at
least one exercised case in the module's own spoken-punctuation gate, and
a brand new public reply function will always trip it (the same
regression the "unverifiable_claim" story hit and fixed for the identical
reason). Fixed by adding anger_reply() to both the gate's yielded cases
(8 cases: both branches x 4 languages) and its "exercised" allow-list, in
tests/test_spoken_punctuation.py -- mirroring doctor_personal_request_
reply()'s own precedent for a two-branch function. Verified: tests/
test_spoken_punctuation.py now passes in full, including this test.
